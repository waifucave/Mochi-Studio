# Mochi Studio 0.1.0: the first pre-release

Mochi Studio is an open-source live-avatar app for models made with Live2D
Cubism (`.moc3` and `.model3.json`), built on the Mochi2D runtime. It
animates your avatar with your webcam and microphone, and you stream it
with OBS. This is its first pre-release: the desktop app for Linux,
Windows and macOS.

**These apps are not signed.** Your system warns about them the first time
you open them. The warning does not mean anything harmful was found; it
means the app does not carry a publisher's signature yet. Each package has
a `HOW-TO-OPEN` note for its system with the steps. In short:

- **Windows** shows "Windows protected your PC" (SmartScreen): choose
  **More info**, then **Run anyway**.
- **macOS** won't open an app from an unidentified developer the first
  time: right-click the app, choose **Open**, then **Open** again. On
  macOS 15 and later, if there is no **Open** button, use **Open Anyway**
  in System Settings → Privacy & Security.
- **Linux** doesn't warn, but the downloaded file must be made executable
  first (`chmod +x`).

**To try it without installing anything from here,** run Mochi Studio in a
browser from the source: `npm ci`, `npm run fetch:models`, `npm run dev`
(Node.js 22 or later; see the README's Getting started).

## The files

| System  | File                                       | Runs on                               |
| ------- | ------------------------------------------ | ------------------------------------- |
| Linux   | `Mochi-Studio-0.1.0-linux-x86_64.AppImage` | 64-bit Intel and AMD (x86_64)         |
| Windows | `Mochi-Studio-0.1.0-windows-x64.zip`       | 64-bit Windows 10 and 11              |
| macOS   | `Mochi-Studio-0.1.0-macos-arm64.zip`       | Apple silicon Macs, macOS 13 or later |

Each comes with `HOW-TO-OPEN-<system>.txt`. There are no installers: on
Windows and macOS, unzip the app and run it; on Linux, run the AppImage.
The app does not update itself; new versions appear on this page.

## What works

**The same on every system** (the app's own browser tests run these
in Chromium on every change):

- loading a model from a folder or a zip, and the sample model «Mochi»
  (**Try the sample model** on the empty stage);
- face tracking from the webcam, hand tracking and gesture hotkeys, and
  lip sync from the microphone, all on this computer: camera pictures and
  sound are never recorded, stored or sent;
- the mapping editor, items, hotkeys and on-screen buttons, expressions,
  motions and physics;
- the import of a model's settings files made for VTube Studio;
- plugins made for VTube Studio, and the agent API (an MCP server and a
  WebSocket API), both off until you switch them on;
- **output views for OBS:** the address in the Camera tab, added in OBS as
  a Browser Source, shows the avatar alone with a transparent or chosen
  background. This is how to get the avatar into OBS on every system.

**Each package was started on GitHub's runner for its system** (Linux:
Ubuntu, under a virtual display; Windows Server 2025; macOS on Apple
silicon): its built-in bridge answered with version 0.1.0, served the
app's pages, and the app's window connected to it. The packages have not
been tried on a person's computer by the project yet.

### Windows

- **Spout2 output** to OBS's Spout2 plugin and other Spout2 programs
  (Camera tab → Spout2), transparent. Tested on GitHub's Windows runner: a
  Spout2 receiver reads the app's senders back, premultiplied and
  transparent. That runner has no graphics card, so the app draws in
  software there. An output larger than the screen (1920 × 1080 on its
  1024 × 720) used to stop the app's window answering. Now, when the
  computer can't keep up, the output's frame rate comes down instead, and
  the app says "Spout2 is sending at N frames a second: this computer can't
  keep up at this size". On that runner the window answers within a second
  throughout (by its own measure, at most 79 ms late in 20 runs), but a
  1920 × 1080 output sends 0 to 12 frames a second with the window shown:
  there, pick a size that fits the screen.
  Not yet tried on a PC with a graphics card, where frames stay on the
  card.
- **A virtual camera** ("Mochi Studio Camera") for call apps: Camera tab →
  Virtual camera → **Install**, with one administrator prompt from Windows.
  On Windows 11 it is the system's own virtual camera (Media Foundation);
  **Also for older apps** adds a DirectShow camera, which is also what
  Windows 10 gets. Both are tested end to end on GitHub's Windows runner
  (Windows Server 2025): registered as Install does, and read back by
  ffmpeg and by a Media Foundation reader. **Not yet tried** on a person's
  PC or in call apps (Zoom, Discord, Teams).
- If Windows Firewall asks: the app listens only on this computer
  (127.0.0.1); you can choose Cancel and OBS on the same computer still
  works.

### macOS

- **The virtual camera does not work in this build.** macOS runs a Camera
  Extension only in an app that is signed and notarized, and these builds
  are not, so Install is refused. It comes with the first signed build.
  Until then, use the **output view in OBS** (above); OBS's own **Start
  Virtual Camera** can pass an OBS scene on to call apps (an OBS feature,
  not tested by this project).
- No Spout2 (Windows only).
- macOS asks once for the camera and the microphone when you first use
  them, and for screen recording if you use light from the screen.
- The package is built for Apple silicon only (M1 and later), and needs
  macOS 13 or later.

### Linux

- **A virtual camera** for call apps, through `v4l2loopback`, a kernel
  module you install and load yourself once (the app never asks for
  `sudo`):

  ```sh
  sudo apt install v4l2loopback-dkms      # Debian, Ubuntu (Fedora: dnf, from RPM Fusion; Arch: pacman)
  sudo modprobe v4l2loopback devices=1 video_nr=10 card_label="Mochi Studio Camera" exclusive_caps=1
  ```

  Then Camera tab → Virtual camera. Tested on GitHub's Ubuntu runner with
  the real device, read by ffmpeg as a call app would. With Secure Boot,
  your distribution asks you to sign the module when it installs.

- If the AppImage says FUSE is missing, install `libfuse2` (Ubuntu 22.04
  and later: `libfuse2t64`), or run it with `--appimage-extract-and-run`.
- No Spout2 (Windows only).

## Playing together (collaborations)

Up to six people's avatars on one stage, over WebRTC. **It needs a
signaling server, and neither the app nor the project provides one.** One
of you runs one, or you use one that someone you trust runs:

- the server is included: `npm run collab:server` (Node.js), or as a
  Cloudflare Worker; see `docs/collaboration.md`, "Hosting a server";
- everyone puts its address in **Settings → Collab → Signaling server**; an
  invitation link carries it, so people joining by link need nothing else;
- for people on other networks, the server needs a domain with TLS and a
  TURN relay beside it; without TURN, people on strict networks can't
  join.

## Not in this version

- **Signed builds.** They need the signing certificates and Apple's setup,
  which come later; then the warnings above go away, and the macOS camera
  works.
- **Installers and updates:** unzip or run the file; download new versions
  here.
